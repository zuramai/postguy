---
title: Getting started
description: A guided tour from first launch to a headless collection run - send a request, use an environment, add tests and run them.
---

This tutorial takes about ten minutes. You need Postguy installed ([Installation](/getting-started/installation)) and an internet connection for the public test service `httpbin.org`. In the shortcuts below, `Cmd` is the Command key on macOS and `Ctrl` elsewhere.

::steps

### Launch Postguy and find your workspace

Start the app. With no `--workspace` option, it uses `./postguy-workspace` if that folder exists where you launched it, otherwise `~/postguy-workspace` (`%USERPROFILE%\postguy-workspace` on Windows). The folder is created on first use. It holds all your collections, environments and settings as plain files.

A new workspace opens on a welcome screen with three buttons, **New HTTP request**, **Import…** and **Settings…**, and the hint "Cmd/Ctrl+N new request · Cmd/Ctrl+I import · Cmd/Ctrl+K commands". The status line at the bottom right reads "Ready".

### Create a collection and a request

Press `Cmd/Ctrl+N`. In an empty workspace this creates a collection named **New Collection** with a request named **New Request**, and opens the request in a tab. The request is an HTTP `GET`.

To create things by hand, use the **+** button at the top of the sidebar. Its menu offers **New HTTP request**, **New gRPC request**, **New WebSocket request**, **New collection** and **New environment**. Right-click a collection in the sidebar for **Rename** (`F2`), **Add request**, **Add folder**, **Run**, **Duplicate** and **Delete**. Rename the collection to `My API`.

### Send a request

In the request tab, enter this URL and press **Send** (or `Cmd/Ctrl+Enter`):

```text
https://httpbin.org/get
```

The response appears below the request, with the status, time and size.

### Read the response

The response viewer has four tabs:

| Tab | Shows |
| --- | --- |
| **Body** | The body in four modes: **Pretty**, **Raw**, **Preview** and **Hex** |
| **Cookies** | Cookies set by the response (with a count) |
| **Headers** | Response headers (with a count) |
| **Test Results** | Passed and failed tests, shown as `Test Results (passed/total)` once any test has run |

### Save the request

Press `Cmd/Ctrl+S`. A request tab with unsaved edits shows a dirty marker. The collection runner and the CLI use the saved version, so save before you run.

### Add an environment

An environment holds variables you can reuse in any request.

1. In the sidebar, open the **+** menu and choose **New environment**. It opens as a tab named **New Environment**; edit the name at its top.
2. In the variables table (columns **Variable** and **Value**), add a variable `baseUrl` with the value `https://httpbin.org`.
3. In the selector at the right of the tab strip, which reads **No environment**, choose your environment.

Now change the request URL to use the variable and send again:

```text
{{baseUrl}}/get
```

`{{name}}` is replaced when you send. See [Variables](/guide/variables) for the lookup order and secret variables.

### Add a test

Open the **Tests** tab of the request. The **Assertions** table has one row per check, with the columns expression, operator and value. Add a row:

| Expression | Operator | Value |
| --- | --- | --- |
| `res.status` | equals | `200` |

Next, open the **Scripts** tab and put this in the **Post-response** editor:

```js
pm.test("status 200", () => pm.response.to.have.status(200))
```

Send the request again and open **Test Results**: both checks are listed with a `PASS` or `FAIL` badge. Save the request. See [Scripts and tests](/guide/scripts-and-tests).

### Run the collection in the Runner

Right-click the collection in the sidebar and choose **Run**. You can also press `Cmd/Ctrl+K` and choose **Open collection runner**.

The Runner tab lets you pick the **Collection**, the **Environment**, which **Requests** to include, **Iterations**, **Delay**, a **Data file** and **Stop on error**. Select your environment and press **Run My API**. Results appear on the right, filtered by **All**, **Passed**, **Failed** or **Skipped**, with a **Download report** section for CSV, Excel, PDF, HTML, JSON and JUnit. See [Collection runner](/guide/collection-runner).

### Run it headlessly

The CLI runs the same engine without a window. Close the app first, because only one process can open a workspace at a time. Then run:

```sh
postguy-cli run --collection "My API" --workspace ~/postguy-workspace --reporters cli,junit --out reports
```

`--collection` takes a collection id or its exact name. If the name matches more than one collection, use an id. `--environment` takes an environment id or name the same way. Without it, the run uses the workspace's active environment, which is the one selected in the app, so selecting your environment before you close the app is enough; to be explicit, add `--environment "New Environment"`.

The `cli` reporter prints a summary to the terminal, and `junit` writes `reports/postguy-run-<run id>.xml`. The exit code is `0` when everything passed, `1` when a request or test failed and `2` for a usage error such as an unknown collection name.
