## macOS says the app could not be verified

Release builds are not notarized, so Gatekeeper blocks a file you downloaded in a browser. Do one of these:

- Remove the quarantine flag: `xattr -dr com.apple.quarantine /Applications/Postguy.app`.
- Open **System Settings**, then **Privacy & Security**, and choose **Open Anyway**.
- Download with `curl` and unpack with `ditto`, which never sets the flag. The commands are on [Installation](/getting-started/installation).

## Windows shows "Windows protected your PC"

The installer is not signed, so SmartScreen warns. Choose **More info**, then **Run anyway**. Verify the file against `SHA256SUMS.txt` first if you want to be sure; see [Installation](/getting-started/installation).

## "workspace already open by pid …"

A workspace can be open in only one process at a time. Opening it takes a lock file at `<workspace>/.postguy/lock`, which holds the process id and a start time. The full message is:

```text
workspace already open by pid 1234; close that instance or remove <workspace>/.postguy/lock if it is gone
```

- Close the other Postguy window, or stop the `postguy-cli` command that has the workspace open.
- A lock is taken over automatically when its process no longer exists or the lock is older than three minutes. If Postguy crashed, starting it again is normally enough.
- If a process was killed and the message persists, delete the `lock` file by hand.

## A file was corrupt

Postguy never silently drops or repairs a data file.

- If a document, settings or session file cannot be read, it is renamed next to the original as `<name>.corrupt-<time>`, the app starts with a default in its place, and a note says so (for settings: "settings file corrupt; moved to …").
- Every save is atomic. The previous version is kept as `<name>.bak`, one generation deep. To go back, close Postguy and copy the `.bak` over the file.
- A `.corrupt-<time>` file is kept for you to inspect or repair; Postguy does not read it again.

See [Workspace](/guide/workspace) and [Workspace format](/reference/workspace-format).

## TLS or certificate errors

| Symptom | What to check |
| --- | --- |
| Certificate not trusted for a private CA or a self-signed server | **Settings** (`Cmd/Ctrl+,`), **Certificates**, **Custom CA bundle (PEM)**: the file is added to the system roots for every request |
| A client certificate is rejected or not read | **Settings**, **Certificates**, **Client certificate**: give a PEM chain and a PEM private key (PKCS#8, PKCS#1 or SEC1). Encrypted keys and PFX files are not supported yet |
| You need to test a server with an invalid certificate | Turn off **SSL certificate verification** in **Settings**, or **Enable SSL certificate verification** in a single request's **Settings** tab. Turn it back on afterwards; with verification off, any server can impersonate the one you meant to reach |

## Requests fail behind a proxy

By default Postguy uses the system proxy settings, read from the `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` and `NO_PROXY` environment variables (upper or lower case). A graphical launcher may not pass your shell's variables to the app, so start Postguy from a terminal to test. Alternatively, set **Proxy mode** to **Custom proxy** in **Settings**, **Proxy**. A custom proxy wins over the environment. The proxy a request actually used is logged in the Console. Details: [Cookies, proxy and certificates](/guide/cookies-proxy-certificates).

## File dialogs do not open on Linux or FreeBSD

Open and Save dialogs use `xdg-desktop-portal`. Install it and a backend that matches your desktop. The `.deb` lists `xdg-desktop-portal` as a recommended package. In the Flatpak build, dialogs always go through the portal because the sandbox has no filesystem access.

## The window does not start on Linux

Postguy loads X11 or Wayland, xkbcommon and EGL/GL libraries at run time. Check that the libraries listed under Linux on [Installation](/getting-started/installation) are installed. Start the app from a terminal so that any error message is visible.

## Scripts do nothing

**Settings**, **General** has a **Disable scripts** setting that skips pre-request and post-response scripts for every request and run. Check that it is off. Scripts also run only for HTTP requests, not gRPC or WebSocket. See [Scripts and tests](/guide/scripts-and-tests).

## Where to look for diagnostics

Postguy writes no log file.

- **Console**: the **Console** button at the bottom left, or `Cmd/Ctrl+Alt+C`, lists request summaries, logs, warnings and errors. Script `console.log` output appears here. Filters: All, Requests, Logs, Warnings, Errors.
- **Status line**: the text at the bottom right of the window shows the result of the last action ("Ready", "Created request", and error messages).
- **Import report**: after an import, the report lists what was changed, skipped or unsupported.
- **Terminal**: messages that cannot be shown in the window, such as "control channel disabled", go to standard error. Start the app from a terminal to see them.
- **CLI**: `postguy-cli` prints errors to standard error and exits `1` for a failure or `2` for a usage error. See the [CLI reference](/reference/cli).

If none of this helps, open an issue at [github.com/zuramai/postguy/issues](https://github.com/zuramai/postguy/issues). Never paste real tokens, API keys or private responses.
