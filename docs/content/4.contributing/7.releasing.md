Releases are built by [`.github/workflows/release.yml`](https://github.com/zuramai/postguy/blob/main/.github/workflows/release.yml). The canonical notes live in [`packaging/README.md`](https://github.com/zuramai/postguy/blob/main/packaging/README.md), which stays in the repository next to the scripts; this page summarises it.

## Release flow

The workflow runs when a tag matching `v*` is pushed (the tag names the version), or by hand through `workflow_dispatch` with an optional version override such as `0.2.0-rc.1`.

::steps
### Set the version

The version lives in exactly one place: `[workspace.package] version` in the root `Cargo.toml`.

```sh
cargo xtask version          # print it
cargo xtask version set X.Y.Z
```

The format is `X.Y.Z` or `X.Y.Z-pre.release`. A version containing `-` marks the GitHub release as a pre-release. In deb and rpm packages a pre-release such as `0.2.0-rc.1` becomes `0.2.0~rc.1`.

### Push the tag only

```sh
git tag v1.2.3
git push origin v1.2.3
```

Do not create the GitHub release by hand. The workflow creates a draft and refuses to update a release that is already published.

### Wait for the jobs

`version` resolves and validates the version. `macos`, `windows` (x64, x86, arm64) and `linux` (x86_64, aarch64) build in parallel. `flatpak` builds from the Linux tarball and therefore needs `linux`. `release` then collects every artifact.

### Publish the draft

The `release` job writes `SHA256SUMS.txt` over all artifacts and creates the draft release `v<version>` titled `Postguy v<version>` with generated notes. Re-running for a tag whose release is still a draft replaces its assets. Review the draft and publish it by hand.
::

A manual run with a version override applies it with `cargo xtask version set` inside the job, so `Cargo.toml` in the repository is not changed.

## Artifacts

Files appear in `dist/release/`.

| Platform | Script | Artifacts |
| --- | --- | --- |
| macOS universal | `packaging/macos/package.sh --arch universal` | `postguy-<v>-macos-universal.dmg`, `postguy-<v>-macos-universal.zip` (the app), `postguy-cli-<v>-macos-universal.tar.gz`. Developer ID codesign and notarization. |
| Windows x64, x86, arm64 | `packaging/windows/package.ps1 -Arch <arch>` | `postguy-<v>-windows-<arch>.msi` (WiX v5), `postguy-<v>-windows-<arch>.zip` (portable), `postguy-cli-<v>-windows-<arch>.zip`. Azure Trusted Signing or a PFX. |
| Linux x86_64, aarch64 | `packaging/linux/package.sh` | `postguy-<v>-linux-<arch>.AppImage` (plus `.AppImage.zsync` when `zsyncmake` is present), `.deb`, `.rpm`, `.tar.gz`, and `postguy-cli-<v>-linux-<arch>.tar.gz`. |
| Flatpak | `packaging/linux/flatpak-bundle.sh` | `postguy-<v>-linux-<arch>.flatpak` |

Not built: WebAssembly (there is no web build), riscv64, FreeBSD and Arch. FreeBSD users [build from source](/getting-started/build-from-source).

Build hosts: `macos-15` for macOS (the universal binary cross-compiles x86_64 on it), `windows-latest`, `ubuntu-22.04` and `ubuntu-22.04-arm` for Linux (so packages need glibc 2.35 or newer), `ubuntu-24.04` and `ubuntu-24.04-arm` for Flatpak. The Linux job uses the public `storytold/craft-common-actions/actions/install-linux-deps` action, the one outside dependency, to install build libraries and nfpm.

Icons are derived at packaging time from `assets/logo`; no generated icon is committed.

## Signing

Signing secrets are optional. Without them the scripts warn and ship unsigned (ad-hoc signed on macOS), so a release works with no secrets. Set them as secrets of the repository's `release` environment, which must exist (Settings, Environments) even when empty.

| Platform | Secrets |
| --- | --- |
| macOS | `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD`, `KEYCHAIN_PASSWORD`, `APPLE_ID`, `APPLE_PASSWORD`, `APPLE_TEAM_ID` |
| Windows (Azure Trusted Signing) | `AZURE_TENANT_ID`, `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`, `AZURE_SIGNING_ENDPOINT`, `AZURE_SIGNING_ACCOUNT`, `AZURE_CERT_PROFILE` |
| Windows (PFX alternative) | `WINDOWS_CERTIFICATE`, `WINDOWS_CERTIFICATE_PASSWORD` |

Notarization needs a real signing identity plus `APPLE_ID`, an app-specific `APPLE_PASSWORD` and `APPLE_TEAM_ID`. The macOS job also runs `packaging/macos/verify.sh` after packaging.

::note
Do not describe a release as signed or notarized on the install pages unless the draft's artifacts were actually built with these secrets.
::

## Running the scripts locally

`packaging/env.sh` is shared setup for the bash scripts. It reads the version from the root `Cargo.toml` (override with `POSTGUY_VERSION`) and exports `DIST` (default `dist/release`), the application id `io.github.zuramai.postguy` and the build date and commit.

::tabs
:::tabs-item{label="macOS"}
```sh
packaging/macos/package.sh --arch universal      # or aarch64, x86_64
packaging/macos/package.sh --arch aarch64 --skip-build
packaging/macos/verify.sh --arch universal       # add --require-notarized to demand tickets
```

Without `MACOS_SIGN_IDENTITY` the app is ad-hoc signed and Gatekeeper rejects it on other Macs. The minimum system version is macOS 11.0.
:::

:::tabs-item{label="Windows"}
Needs the Rust MSVC toolchain and target, and WiX v5. The Windows SDK (`signtool.exe`) is needed only for signing.

```powershell
dotnet tool install --global wix --version 5.0.2
wix extension add -g WixToolset.UI.wixext/5.0.2
wix extension add -g WixToolset.Util.wixext/5.0.2

pwsh packaging/windows/package.ps1 -Arch x64     # or x86, arm64
pwsh packaging/windows/package.ps1 -Arch x86 -SkipBuild
pwsh packaging/windows/test-msi.ps1 dist/release/postguy-0.1.0-windows-x64.msi
```

`test-msi.ps1` needs an elevated shell: it installs the MSI silently into a temporary folder, checks the result, runs the CLI and uninstalls. `package.ps1` runs it for x64 and x86 builds. The arm64 build is cross-compiled and needs the MSVC ARM64 build tools. Binaries link the C runtime statically, so no Visual C++ redistributable is required.
:::

:::tabs-item{label="Linux"}
Needs `cargo`, `curl`, `nfpm` for deb and rpm, and `appimagetool` for the AppImage (a pinned release is downloaded and checked against its SHA-256 if missing; override with `APPIMAGETOOL=/path`). Build on an old distribution, as CI does with Ubuntu 22.04, so the binaries run on newer ones.

```sh
packaging/linux/package.sh
packaging/linux/package.sh --skip-build --formats "deb rpm"   # formats: appimage deb rpm tar cli
```
:::

:::tabs-item{label="Flatpak"}
Needs `flatpak`, `flatpak-builder` and `librsvg2-common`. The bundle is built for the host architecture from a Linux tarball, which `package.sh --formats tar` creates first. The freedesktop runtime and SDK named in the manifest are installed per user from Flathub.

```sh
packaging/linux/package.sh --formats tar
packaging/linux/flatpak-bundle.sh                 # uses dist/release/postguy-<v>-linux-<arch>.tar.gz
packaging/linux/flatpak-bundle.sh --no-test path/to/postguy-<v>-linux-<arch>.tar.gz
```

Unless you pass `--no-test`, the bundle is installed per user and the sandbox's files are listed as a smoke test.
:::
::

Optional tools for the Linux script: `desktop-file-validate`, `appstreamcli` and `zsyncmake`.

Packaging scripts are not part of `cargo xtask ci`. Verify a package by installing it on a clean machine and running `postguy-cli tools` (the CLI has no `--version` flag).
