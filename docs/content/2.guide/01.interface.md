Postguy is one window with a header on top, a sidebar on the left, a tab strip with the active document in the middle, and a bottom bar. The default window size is 1280 x 800 and the minimum is 900 x 560.

| Region | What it holds |
|---|---|
| Header | Workspace name, the `Search Postguy` button (command palette), the Settings gear. On Windows, Linux and FreeBSD it also holds the File / Edit / View / Window / Help menu row. |
| Sidebar | `COLLECTIONS`, `ENVIRONMENTS` and `HISTORY` sections with a filter field. |
| Tab strip | One tab per open document, the tab search button, the `Vars` quick look and the environment selector. |
| Central panel | The request builder and response viewer, or an environment, collection, settings, cookies, trash or runner tab. |
| Right panel | The code snippet panel (hidden by default). |
| Bottom bar | `Sidebar`, `Console`, `Cookies`, `Globals`, `Trash` buttons on the left; `Two-pane`, `Right` and a status text on the right. |

## Header

- The workspace name is the folder name of the open workspace. See [Workspace](/guide/workspace) for how the folder is chosen.
- The back and forward arrows are present but disabled.
- `Search Postguy` opens the command palette (also `Cmd/Ctrl+K`).
- The gear opens the Settings tab. See [Settings](/guide/settings).
- On macOS the header doubles as the title bar and the menu bar is the native one. On other systems the menu row is drawn inside the header.

## Welcome screen

With no tab open the central panel shows `New HTTP request`, `Import…` and `Settings…`, and the reminder `Cmd/Ctrl+N new request · Cmd/Ctrl+I import · Cmd/Ctrl+K commands`.

## Sidebar

The three sections have collapsible headers and draggable splitters between them. Section open state and heights are saved in the session file.

### Collections

- A tree of collections, folders and requests. Requests show a method label: `GET`, `POST`, `PUT`, `PATCH`, `DEL`, `HEAD`, `OPT`, `gRPC` or `WS`.
- The caret expands folders. For a request with saved examples it expands the examples.
- Click a row to open it in a tab; Enter opens the focused row. Opening a document that is already open just activates its tab.
- The filter field (`Filter`) matches request and environment names, the method label and the URL of HTTP requests. While a filter is active the tree shows only matches and their parents.
- The `+` button opens `New…`: `New HTTP request`, `New gRPC request`, `New WebSocket request` (enabled when a collection or folder is selected), `New collection`, `New environment`. The import button opens the import dialog.
- The hover `...` button and a right-click open the same context menu. See [Collections](/guide/collections) for the actions.

### Environments

One row per environment. The active environment is marked. The context menu has `Set active`, `Rename`, `Duplicate`, `Export`, `Delete` and `No environment`.

### History

Every send from the request builder adds a row, newest first. A row shows the method, the URL, the time, the status and the duration. The filter also matches the time text and the history id. The context menu has `Open` and `Delete`.

::note
Opening a history row creates a tab titled with the method and path. Re-opening the stored request from it is not available yet; the tab shows a notice instead. See [HTTP requests](/guide/http-requests#history-and-console) for what history stores.
::

### Keyboard and mouse

| Input | Action |
|---|---|
| Up / Down | Move the focus. |
| Right / Left | Expand / collapse a folder, or a request's examples. |
| Enter | Open the focused row. |
| F2 | Rename inline. |
| `Cmd/Ctrl+C`, `Cmd/Ctrl+X`, `Cmd/Ctrl+V` | Copy, cut, paste items. |
| Delete | Delete the focused row (a history row deletes its entry). |
| `Cmd/Ctrl`-click, Shift-click | Toggle or range-select several rows. |
| Drag | Move an item. `Cmd/Ctrl`-drag copies it. |

These keys only work while no text field has focus.

## Tab strip

- Each open document gets a tab: request, environment, globals, collection, folder, settings, cookies, trash or runner.
- A dot on a tab means unsaved changes; it turns into the close button on hover. Closing such a tab opens `Unsaved changes` with `Cancel`, `Don't save` and `Save`.
- Middle-click closes a tab. Drag a tab to reorder.
- `Cmd/Ctrl+W` closes the active tab, `Cmd/Ctrl+Shift+T` reopens the last closed one, `Cmd+Tab` / `Cmd+Shift+Tab` move to the next or previous tab.
- The chevron button (`Search tabs`) lists `Open tabs` and `Recently closed`. The list of closed tabs keeps the last 20; the menu shows 10.
- Tabs and layout are restored on the next start. See [Workspace](/guide/workspace#session-restore).

::note
The tab model supports preview tabs (underlined title, replaced by the next preview), but the sidebar currently opens every document as a permanent tab.
::

## Environment selector and Vars

At the right end of the tab strip:

- The selector shows the active environment or `No environment`. Its menu has a search field, `No environment`, the list and `+ Create new environment`. Choosing one applies to every request.
- `Vars` (the eye button) opens a quick look at the variables of the active environment, the globals and the collection of the active request. Secret values are masked until you press `Reveal secrets`. Clicking a value copies it.

See [Variables](/guide/variables).

## Request and response layout

By default the builder is on top and the response viewer below it. `Two-pane` (bottom bar, `Cmd/Ctrl+Alt+V`) puts them side by side. The layout toggle is not saved between sessions.

## Bottom bar

| Button | Action |
|---|---|
| `Sidebar` | Show or hide the sidebar (`Cmd/Ctrl+\`). |
| `Console` | Show or hide the console panel (`Cmd/Ctrl+Alt+C`). |
| `Cookies` | Open the cookie manager tab. See [Cookies, proxy and certificates](/guide/cookies-proxy-certificates). |
| `Globals` | Open the globals editor tab. |
| `Trash` | Open the trash tab. |
| `Right` | Show or hide the right panel with the generated [code snippet](/guide/code-snippets). |
| `Two-pane` | Toggle the side-by-side layout. |

The runner has no bottom-bar button: open it from a collection or folder (`Run`) or with the command `Open collection runner`. See [Collection runner](/guide/collection-runner).

### Console

The console panel shows what the engine did: requests, script `console.*` output, warnings and errors. Filters are `All`, `Requests`, `Logs`, `Warnings` and `Errors`; it also has a search field, a `Timestamps` switch and `Clear`. The console keeps the newest 5000 entries from the last 24 hours. Secret values are masked.

## Command palette

`Cmd/Ctrl+K` (when no text field has focus) or the header search button opens it.

- Type to filter. Matching is a case-insensitive subsequence match.
- It lists open tabs, recently closed tabs, collections, folders, requests and environments first, then commands. A `>` prefix limits the list to commands.
- At most 12 results are shown. Up / Down move, Enter runs, Esc closes. Commands show their group and shortcut as a hint.

The full command list and every shortcut is in [Keyboard shortcuts](/guide/keyboard-shortcuts).

## Menus

The menus File, Edit, View, Window and Help run the same commands as the palette. On macOS they live in the native menu bar; on Windows, Linux and FreeBSD they are the in-app row in the header. The Window menu has placement commands (halves, quarters, thirds, fill, center). `Help › Documentation` opens this site.

## Themes and zoom

- `Settings › Themes` has `Dark`, `Light` and `System`. System follows the operating system.
- `Interface zoom` scales the whole UI from 80% to 200%. `Cmd/Ctrl+=`, `Cmd/Ctrl+-` and `Cmd/Ctrl+0` zoom in, out and reset. See [Settings](/guide/settings).
- Poppins is the one embedded UI font; code uses a monospace face at the `Code font size` setting (9 to 24 px).

::note
Remembered window position and size are not implemented yet, and neither is the shortcut-conflict check.
::

::tip{title="Headless"}
The UI state can be inspected and driven from outside with the opt-in [UI control channel](/reference/ui-control-channel) (`postguy-cli ui`). The data behind the sidebar is available through the tools `collection_list`, `env_list`, `history_list` and `console_get`.
::
