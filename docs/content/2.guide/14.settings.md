Open Settings with `Cmd/Ctrl+,` or the command `Open settings`. It opens as a tab with a navigation column. Every change is saved at once. There is no Save button.

## Pages

| Page | Rows |
|---|---|
| General | **Request:** HTTP version, Request timeout, Max response size, SSL certificate verification, Automatically follow redirects, Disable cookies, Send no-cache header. **Working directory:** Location, Read files outside the working directory. **History:** Save response bodies in history. **Scripts:** Disable scripts. |
| Themes | Theme (Dark, Light, System), Interface zoom, Code font size. |
| Shortcuts | A read-only list of every registered shortcut, grouped. See [Keyboard shortcuts](/guide/keyboard-shortcuts). |
| Data | Reset settings. It restores every setting to its default. Collections, environments and history are not touched. |
| Certificates | Custom CA bundle (PEM), Certificate chain (PEM), Private key (PEM). |
| Proxy | Proxy mode. With `Custom proxy`: Protocol, Host, Port, Username, Password, Apply to HTTP, Apply to HTTPS, Bypass list. |
| About | Version, licence (`MIT OR Apache-2.0`), privacy note (`Offline. No telemetry, no update check`), pointer to the third-party notices. |

## Where the file lives

Settings are per workspace, in `<workspace>/.postguy-config/settings.json`. The same folder holds `session.json` and `recent.json`. See [Workspace](/guide/workspace) and the [workspace format](/reference/workspace-format).

- Keys are camelCase.
- Unknown keys, including ones written by newer versions, are kept and written back.
- A missing file means all defaults.
- Postguy reads up to 8 MiB of the file. If it cannot parse the file, it renames it to `settings.json.corrupt-<number>` in the same folder and starts with defaults.
- The app rewrites the file on every change. Edit it by hand only while Postguy is closed.

## Per-request settings

Each HTTP request also has a Settings tab. It holds HTTP version, SSL verification, redirect options, `Encode URL automatically`, `Disable cookie jar`, timeout and max response size. When you send a request, the global and per-request values combine like this:

| Setting | Rule |
|---|---|
| SSL verification, follow redirects | Both must be on. |
| Disable cookies | Either one disables the jar. |
| Timeout | The request's value if not `0`, otherwise the global one. |
| Max response size | The request's value if it differs from 50, otherwise the global one. |
| HTTP version | The request's choice, or the global one when the request says `Auto`. |

See [HTTP requests](/guide/http-requests).

## Headless

No automation tool edits settings. Tools that depend on them (for example `request_send` and `collection_run`) read them from the opened workspace's `.postguy-config/settings.json`.
