This site is a [Docus](https://docus.dev) project (a Nuxt layer) in the `docs/` folder of the repository. It is outside the product and outside the Rust build.

## Layout

| Path | Purpose |
| --- | --- |
| `docs/content/` | All pages, as Markdown. |
| `docs/content/index.md` | Landing page. |
| `docs/content/<N>.<section>/` | One folder per section: `1.getting-started`, `2.guide`, `3.reference`, `4.contributing`. Each has a `.navigation.yml` with the section `title` and `icon`. |
| `docs/nuxt.config.ts` | Site name and URL, the asset folders served from `assets/`, the font list, and switches that keep the build static. |
| `docs/app/app.config.ts` | Header title and logo, GitHub link for "Edit this page", colours. |
| `docs/app/app.css` | Sets Poppins as the sans-serif font. |
| `docs/package.json`, `docs/package-lock.json` | The three npm dependencies: `docus`, `nuxt`, `better-sqlite3`. |

Navigation order comes from the numeric filename prefix, and the prefix is dropped from the route. For example `1.getting-started/2.installation.md` becomes `/getting-started/installation`, and `4.contributing/8.documentation.md` becomes `/contributing/documentation`. Prefixes sort as text, so a folder with ten or more pages zero-pads all of them (`2.guide/01.interface.md` … `2.guide/16.privacy-and-security.md`).

## What `docs/` may contain

[AGENTS.md](https://github.com/zuramai/postguy/blob/main/AGENTS.md) section 5.2 limits the folder to:

- `package.json` and `package-lock.json`;
- `nuxt.config.ts`;
- `app/app.config.ts` and `app/app.css`;
- the `.navigation.yml` file in each section folder;
- Markdown under `content/`.

No Vue components, pages, plugins, server code or other handwritten JS/TS. The only npm dependencies are `docus`, `nuxt` and `better-sqlite3`; adding another needs the owner's approval.

::note
This is a written exception to the "Rust only" rule, which covers the product and the build (`xtask`). It does not allow JS/TS anywhere else.
::

## Preview locally

Node 22 or newer and npm are required.

```sh
cd docs
npm ci
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). Pages reload as you save.

### Reproduce the Pages build

GitHub Pages serves the site under `/postguy/`, so the build sets a base URL:

```sh
cd docs
npm ci
NUXT_APP_BASE_URL=/postguy/ npm run generate
```

The static site is written to `docs/.output/public`. The generated folders `docs/node_modules/`, `docs/.nuxt/`, `docs/.output/` and `docs/.data/` are git-ignored, and `cargo xtask assets` skips them. `nitro.prerender.failOnError` is on, so a broken internal link fails the build.

## Writing rules

::steps
### Frontmatter

Every page has `title` and `description`, and nothing else. Do not add an H1 in the body: Docus renders the title. Start the body with prose or `##`.

### Mustache in code only

Put every double-brace variable and every `{{% ... %}}` shortcode in inline code or a fenced block. In plain prose the Markdown engine treats double braces as a data binding and renders nothing. Avoid bare single-brace attribute-like sequences in prose for the same reason.

### Links

Link between pages with site routes (`/guide/variables`), never relative file paths. Link to repository files with `https://github.com/zuramai/postguy/blob/main/<path>`.

### Icons, images and fonts

Use only `i-lucide-*` icons. Commit no images and no screenshots; the logo in the header is the only picture. Do not add a font.

### Honest status

Check `parity/postman-features.toml` for the feature. Anything `partial` or `planned` gets a note saying what is missing. The MCP server is described as planned only.

### Verify facts in code

Every fact (flag, default, limit, label, shortcut) is checked against the source before it is written. If it cannot be confirmed, leave it out.
::

### Components

| Component | Use |
| --- | --- |
| `::note`, `::tip`, `::warning`, `::caution` | Callouts. |
| `::tabs` with `:::tabs-item{label="macOS"}` | Per-platform instructions. |
| `::steps` | Numbered tutorials; each step starts with a `###` heading. |
| `::code-group` | Alternative snippets side by side. |
| `::card-group` with `:::card{title="..." icon="i-lucide-..." to="/..."}` | Link cards. |

Use tables for lists of facts and fenced blocks with a language tag (`json`, `sh`, `js`, `toml`, `text`).

A callout example:

```md
::warning
Secret variables are not encrypted at rest.
::
```

### Describing other products

Mention Postman only as a factual compatibility statement, for example "imports Postman Collection v2.0 and v2.1". Do not use screenshots of it, comparisons or marketing language, and do not describe behaviour beyond what Postguy's code does. See [Assets and clean-room](/contributing/assets-and-clean-room).

## Logo and fonts

The header logo and the Poppins faces are served from the original files in `assets/logo/` and `assets/fonts/`. They are mapped to the `/logo` and `/fonts` URLs by `nitro.publicAssets` in `nuxt.config.ts`, never copied into `docs/`. `ATTRIBUTION.toml` records this under the `usage` of each file. The configuration also disables the remote font download for Nuxt UI's default face, so Poppins is the only font used, as [AGENTS.md](https://github.com/zuramai/postguy/blob/main/AGENTS.md) section 1.4 requires. Generated social-preview images and the Docus MCP server are switched off for the same reasons (no unattributed font rendering, no server routes on static hosting).

## Publishing

[`.github/workflows/docs.yml`](https://github.com/zuramai/postguy/blob/main/.github/workflows/docs.yml) builds and deploys the site.

| Event | Result |
| --- | --- |
| Pull request touching `docs/**`, `assets/logo/**`, `assets/fonts/**` or the workflow | `npm ci` and `npm run generate` with `NUXT_APP_BASE_URL=/postguy/`. No upload. A broken page fails the check. |
| Push to `main` touching the same paths | The build, then the `public` output is uploaded as the Pages artifact and deployed by `actions/deploy-pages`. |
| Manual dispatch | The build; the deploy job runs when started from `main`. |

The site is published at [zuramai.github.io/postguy](https://zuramai.github.io/postguy/). The in-app Help menu's Documentation item opens this address.

::warning
For the deploy job to succeed, GitHub Pages must be enabled in the repository settings (Settings, Pages) with Source set to "GitHub Actions". Until then the build passes and the deploy fails. This is a one-time manual step for the owner.
::

If the site later moves to a custom domain, change `site.url` in `nuxt.config.ts`, set `NUXT_APP_BASE_URL` to `/` in the workflow and update the documentation address in `crates/ui-egui/src/commands.rs`.

## Keep pages true

User-facing changes update the matching page in the same pull request. When a feature's status changes in `parity/postman-features.toml`, update [Feature status](/reference/feature-status) and the notes on the affected guide page.
