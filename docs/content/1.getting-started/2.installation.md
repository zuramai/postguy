## Verify the download

Every release has a `SHA256SUMS.txt` file with the SHA-256 checksum of each file. Download it next to the file you want, then check:

::code-group
```sh [macOS]
grep "postguy-<version>-macos-universal.zip" SHA256SUMS.txt | shasum -a 256 -c
```

```sh [Linux]
sha256sum -c --ignore-missing SHA256SUMS.txt
```

```powershell [Windows]
Get-FileHash .\postguy-<version>-windows-x64.msi -Algorithm SHA256
# Compare the Hash value with the matching line in SHA256SUMS.txt.
```
::

## Install

::tabs
  :::tabs-item{label="macOS"}
  Requires macOS 11.0 (Big Sur) or newer. The build is universal: one app for Apple Silicon and Intel.

  **Install from the `.dmg`:**

  1. Download `postguy-<version>-macos-universal.dmg` in your browser and open it.
  2. Drag **Postguy** into **Applications**.
  3. Open Postguy. macOS says it "could not verify" the app. Click **Done**.
  4. Open **System Settings**, then **Privacy & Security**.
  5. Scroll down to **Security**. Next to *"Postguy" was blocked*, click **Open Anyway**.
  6. Confirm with your password, then click **Open Anyway** again.

  You only do this once.

  **Alternative: install with `curl`.** Downloading with `curl` does not mark the file as quarantined, so Gatekeeper does not block it:

  ```sh
  VERSION=$(curl -fsSL https://api.github.com/repos/zuramai/postguy/releases/latest | grep -m1 '"tag_name"' | sed -E 's/.*"v([^"]+)".*/\1/')
  curl -fL -o /tmp/postguy.zip "https://github.com/zuramai/postguy/releases/download/v$VERSION/postguy-$VERSION-macos-universal.zip"
  ditto -x -k /tmp/postguy.zip /Applications
  open /Applications/Postguy.app
  ```

  **Alternative: remove the quarantine flag.** If you downloaded the `.dmg` or `.zip` in a browser and macOS says it "could not verify" the app, run:

  ```sh
  xattr -dr com.apple.quarantine /Applications/Postguy.app
  ```

  **Headless CLI.** The CLI is a separate tarball:

  ```sh
  curl -fL "https://github.com/zuramai/postguy/releases/download/v$VERSION/postguy-cli-$VERSION-macos-universal.tar.gz" | tar -xz
  ```
  :::

  :::tabs-item{label="Windows"}
  1. Download the `.msi` for your machine (table below) and run it.
  2. If SmartScreen says "Windows protected your PC", click **More info**, then **Run anyway**.
  3. Finish the installer. Postguy is now in the Start menu.

  | Machine | File |
  | --- | --- |
  | 64-bit Intel/AMD | `postguy-<version>-windows-x64.msi` |
  | 32-bit | `postguy-<version>-windows-x86.msi` |
  | ARM64 | `postguy-<version>-windows-arm64.msi` |

  What the installer does:

  - It is per-machine and installs into `Program Files\Postguy`.
  - It adds a Start menu shortcut.
  - It has an optional feature named "Add postguy-cli to PATH". This puts the install folder on the system `PATH`.

  To skip the `PATH` entry, clear that feature in the installer's feature tree. In an unattended install, pass `ADDLOCAL=Main`.

  Silent install (everything, including the `PATH` entry):

  ```powershell
  msiexec /i postguy-<version>-windows-x64.msi /qn
  ```

  Silent install without the `PATH` entry:

  ```powershell
  msiexec /i postguy-<version>-windows-x64.msi /qn ADDLOCAL=Main
  ```

  Other downloads:

  - `postguy-<version>-windows-<arch>.zip`: portable. Unzip and run, no installer.
  - `postguy-cli-<version>-windows-<arch>.zip`: CLI only.
  :::

  :::tabs-item{label="Linux"}
  Builds exist for x86_64 and aarch64. On ARM machines, use `aarch64` in the file name.

  The packages are built on Ubuntu 22.04 against glibc 2.35. Your system needs glibc 2.35 or newer.

  Pick one:

  ```sh
  # AppImage (any distribution)
  chmod +x postguy-<version>-linux-x86_64.AppImage && ./postguy-<version>-linux-x86_64.AppImage

  # Debian, Ubuntu
  sudo apt install ./postguy-<version>-linux-x86_64.deb

  # Fedora, openSUSE
  sudo dnf install ./postguy-<version>-linux-x86_64.rpm

  # Flatpak
  flatpak install --user ./postguy-<version>-linux-x86_64.flatpak

  # Tarball (a top folder with bin/ and share/)
  tar -xzf postguy-<version>-linux-x86_64.tar.gz
  ```

  `postguy-cli-<version>-linux-<arch>.tar.gz` is the headless CLI alone.

  **Runtime libraries.** The window system and graphics libraries are loaded at runtime.

  - The `.deb` depends on `libc6 (>= 2.35)`, `libgcc-s1`, `libxkbcommon0` and `libegl1 | libgl1`.
  - The `.deb` recommends `libwayland-client0`, `libx11-6`, `libxcursor1`, `libxi6`, `libxrandr2` and `xdg-desktop-portal`.
  - The `.rpm` has matching dependencies.
  - With the AppImage or tarball, install the equivalents yourself.
  - File dialogs go through `xdg-desktop-portal`. Install it and a portal backend for your desktop.

  **Flatpak.**

  - The launcher starts Postguy with `--workspace "${XDG_DATA_HOME:-$HOME/.local/share}/postguy-workspace"`. Inside the sandbox, this is under `~/.var/app/io.github.zuramai.postguy`.
  - The sandbox has network, display and GPU access, but no filesystem access. The portal hands over files you pick in a dialog.
  - Pass `--workspace DIR` to override the location.
  :::

  :::tabs-item{label="FreeBSD"}
  FreeBSD is supported, but no prebuilt package is published. Build from source. See the FreeBSD tab under "Prerequisites per OS" on [Build from source](/getting-started/build-from-source).
  :::

  :::tabs-item{label="CLI only"}
  `postguy-cli` is the headless client, for collection runs, automation tools and CI. It is published on its own:

  | Platform | File |
  | --- | --- |
  | macOS | `postguy-cli-<version>-macos-universal.tar.gz` |
  | Windows | `postguy-cli-<version>-windows-<arch>.zip` (also installed by the MSI) |
  | Linux | `postguy-cli-<version>-linux-<arch>.tar.gz` |

  The CLI has no `--version` or `--help` flag. To check that it runs, use `postguy-cli tools`. It lists the automation tools. See the [CLI reference](/reference/cli).
  :::
::

## Where your data lives

Postguy keeps everything in a workspace folder. At start-up it picks the folder in this order:

1. `--workspace DIR`, if you pass it.
2. `./postguy-workspace`, if that folder exists in the folder you start Postguy from.
3. `~/postguy-workspace` (`%USERPROFILE%\postguy-workspace` on Windows).

If no home folder variable is set, the relative `postguy-workspace` is the last resort.

Installed apps often start in a folder they cannot write to (`Program Files`, `/`). That is why the default is your home folder, not the launch folder.

To use another folder, start the app from a terminal:

```sh
postguy --workspace ~/work/api-workspace                       # Linux, FreeBSD, Windows (if on PATH)
open -a Postguy --args --workspace ~/work/api-workspace        # macOS
```

Only one process can open a workspace at a time.

Settings and the open-tab session live inside the workspace, in `.postguy-config/`. See [Workspace](/guide/workspace) and [Workspace format](/reference/workspace-format).

## Uninstall

| Platform | Remove |
| --- | --- |
| macOS | Delete `/Applications/Postguy.app` |
| Windows (MSI) | Uninstall **Postguy** in Apps & Features (Settings, Apps) |
| Windows (portable) | Delete the unzipped folder |
| Debian, Ubuntu | `sudo apt remove postguy` |
| Fedora, openSUSE | `sudo dnf remove postguy` |
| Flatpak | `flatpak uninstall io.github.zuramai.postguy` |
| AppImage, tarball | Delete the file or folder |

::note
Uninstalling never removes your workspace folder. It is your data. Delete it yourself if you no longer want it.
::
