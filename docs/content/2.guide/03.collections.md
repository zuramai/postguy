A collection groups requests. It can hold folders, folders can hold more folders, and each level can carry its own variables, authorization and scripts. Those settings apply to every request below them. Each collection is one JSON file in the [workspace](/guide/workspace).

## Request types

A request is `HTTP`, `gRPC` or `WebSocket`. The type is chosen when the request is created and cannot be changed afterwards. In the tree an HTTP request shows its method (`GET`, `POST`, `PUT`, `PATCH`, `DEL`, `HEAD`, `OPT`); the others show `gRPC` or `WS`.

- HTTP: [HTTP requests](/guide/http-requests)
- gRPC: [gRPC](/guide/grpc)
- WebSocket: [WebSocket](/guide/websocket)

## Create

| What | How |
|---|---|
| Collection | Sidebar `+` › `New collection`, File › New › New collection. New collections are called `New Collection`. |
| Folder | Right-click a collection or folder › `Add folder`, or `New folder` in the `...` menu of a collection's detail tab. |
| Request | Right-click a collection or folder › `Add request` (HTTP), or select a collection or folder and use sidebar `+` › `New HTTP request` / `New gRPC request` / `New WebSocket request`. |
| Quick request | `Cmd/Ctrl+N` creates `New Request` (HTTP) at the root of the first collection, and creates `New Collection` first when the workspace has none. |

## Organise

- **Rename:** `F2` on a row, or the context menu `Rename`. The name field at the top of a collection or folder tab renames it too. A request is renamed from its builder tab.
- **Duplicate:** context menu `Duplicate` makes a deep copy with fresh ids; the copy is named `<name> Copy`. Duplicating a collection also copies its assets.
- **Copy, cut, paste:** `Cmd/Ctrl+C`, `Cmd/Ctrl+X`, `Cmd/Ctrl+V`, or the context menu. A pasted item gets a unique name under its new parent: `Name`, `Name Copy`, `Name Copy 2`, and so on. Paste on a collection or folder pastes inside it; paste on a request pastes into that request's collection.
- **Move:** drag rows in the sidebar. Dropping on a folder nests the item, dropping between rows reorders. `Cmd/Ctrl`-drag copies instead of moving. A drop into an item's own subtree is refused. A multi-selection (`Cmd/Ctrl`-click, Shift-click) moves together.
- **Delete:** context menu `Delete` or the Delete key. Collections and folders ask you to type `delete`; requests and environments go straight to the [trash](/guide/workspace#trash).
- **Undo:** `Cmd/Ctrl+Z` undoes the last rename or move; `Cmd/Ctrl+Shift+Z` redoes it. Deleting is not undone this way.
- **Other context-menu items:** `Run` (collection or folder), `Export collection`, and for requests `Add example`, `Copy as cURL` and `Open in new tab`.

::note
Favourites, A-Z sorting, a pinned default environment per collection and the examples tree are planned and not available. A collection file already has `favourite` and `pinnedEnvironment` fields, but nothing in the UI reads them. Several context-menu entries from the design (add to favourites, collapse all, reveal in file manager) are missing too.
::

## Collection and folder tabs

Opening a collection or folder opens a detail tab. A dot next to a tab name means it has content. Changes autosave shortly after you stop typing.

The header of the tab has an editable name, a `...` menu (`New request`, `New folder` on collections, `Duplicate`, `Export`, `Delete`) and a `Run` button that opens the [collection runner](/guide/collection-runner) for this collection or folder.

| Tab | Collection | Folder | Content |
|---|---|---|---|
| `Overview` | yes | yes | Number of folders and requests, and a Markdown description. The `Preview` checkbox switches between editing and a plain-text view of the description. |
| `Authorization` | yes | yes | Auth that requests below inherit. A collection defaults to `No Auth`, a folder to `Inherit`. See [Authorization](/guide/authorization). |
| `Variables` | yes | yes | Variables scoped to this collection or folder, with a `Secret` switch per row. See [Variables](/guide/variables). |
| `Scripts` | yes | yes | `Pre-request` and `Post-response` scripts that run for every HTTP request below. See [Scripts and tests](/guide/scripts-and-tests). |
| `Runs` | yes | no | The stored runs of the collection, newest first: time, `PASS`/`FAIL`, passed and failed counts, iterations and duration. Click one to open it in the runner. The newest 20 runs are kept. |
| `Assets` | yes | no | Files for scripts and body shortcodes. |

### Inheritance

Variables, auth and scripts resolve from the outside in:

- **Variables:** a folder variable overrides a collection variable of the same name; the innermost folder wins. See the [precedence table](/guide/variables#precedence).
- **Auth:** a request set to `Inherit` uses the closest folder above it that sets its own auth, else the collection's. `No Auth` stops the search.
- **Scripts:** collection script, then folder scripts from the outermost to the innermost folder, then the request's own script.

## Assets

The `Assets` tab manages files stored in `<workspace>/assets/<collection id>/`. Scripts read them (`pg.assets`, `require`, `fs`) and request bodies embed them with [shortcodes](/guide/variables#shortcodes).

- `Import files…` and `Import folder…` copy files in (a folder keeps its structure). The search field filters the list. Columns are `Path`, `Size`, `Modified`.
- Per row: `Rename`, delete (asks `Delete` or `Cancel`) and `Copy shortcode`, which copies `{{% base64(file('<path>')) %}}` to the clipboard.
- Limits: depth 16, 10,000 files, 100 MiB per file, 2 GiB per import, paths up to 1,024 bytes and 255 bytes per component.
- Every path is checked to stay inside the collection's folder: neither `..` nor symbolic links can reach outside. A replaced or deleted asset keeps one `<name>.bak`, which is never listed.
- Importing a Bruno folder copies its other files here with their relative paths. See [Import and export](/guide/import-export#bruno-collection-folders).

Tools take ids, not names. See [Automation tools](/reference/automation-tools).
