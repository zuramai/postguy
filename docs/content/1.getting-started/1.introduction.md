title: Introduction

Postguy is a Postman-like API client that works completely offline, with Bruno collection support. It is a native desktop application written in Rust with egui, for HTTP, gRPC and WebSocket. You organise requests into collections, use environments and variables, send requests, read responses, write scripts and tests, run collections, and import and export your data. No account is needed, and nothing is synced or reported anywhere.

## What it supports today

| Area | State |
| --- | --- |
| HTTP requests | Full: all common methods, bodies, auth types, per-request settings, cookies, redirects, proxy, TLS |
| Collections, folders, environments, globals | Full, stored as JSON files in a workspace folder |
| Scripts and tests | HTTP requests only, in a sandboxed QuickJS engine (`pm`, `pg`, and Bruno-style `bru`, `req`, `res`, `test`, `expect`) |
| Collection runner | HTTP requests only; gRPC and WebSocket requests are skipped |
| Import | Postman Collection v2.0/v2.1 (plus environments and globals), OpenAPI 3 and Swagger 2 (JSON or YAML), HAR 1.2, cURL, Bruno folders, `.proto` files, zip documents |
| Export | Collections, environments, globals, runs and the whole workspace |
| Code snippets | 8 languages for HTTP requests |
| gRPC | Basic client |
| WebSocket | Basic client |
| Headless use | `postguy-cli` with the same engine as the UI |

::note
"Basic" means the feature exists and works for the common case, with known gaps. The per-feature state, taken from the project's parity checklist, is on [Feature status](/reference/feature-status). Scripts and the runner do not cover gRPC or WebSocket requests yet.
::

## Bruno support

Postguy imports a Bruno collection folder: the `.bru` request files, `bruno.json`, `environments/*.bru` and a `.env` file become a collection, environments and an import report. Other files in the folder are copied into the collection's Assets. The script engine also exposes the Bruno-style globals `bru`, `req`, `res`, `test` and `expect`. See [Import and export](/guide/import-export) and [Scripting API](/reference/scripting-api).

Postguy does not export to the Bruno format.

## Offline and privacy promises

- No telemetry, no crash upload, no update check and no cloud sync.
- The app makes no network request that you did not start. Sending a request, running a collection, fetching an OAuth 2.0 token, gRPC reflection and similar actions are the only network use.
- Everything lives in a workspace folder on your disk. See [Workspace](/guide/workspace).
- Secret variable values are kept apart from the documents so you can share a collection without them. They are not encrypted at rest.

Details are on [Privacy and security](/guide/privacy-and-security).

## Platforms

Postguy runs natively on macOS (11.0 or newer), Windows, Linux and FreeBSD. There is no web or WebAssembly build.

| Platform | How you get it |
| --- | --- |
| macOS (Apple Silicon and Intel) | Universal `.dmg` or `.zip` from the releases page |
| Windows (x64, x86, arm64) | `.msi` installer or portable `.zip` |
| Linux (x86_64, aarch64) | AppImage, `.deb`, `.rpm`, Flatpak bundle or tarball |
| FreeBSD | Build from source; no prebuilt package is published |

See [Installation](/getting-started/installation) and [Build from source](/getting-started/build-from-source).
