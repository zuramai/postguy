A variable is a named value that you write into a request as `{{name}}`. Postguy replaces it when the request is sent. Use variables for base URLs, tokens, ids and anything that changes between environments.

```text
{{baseUrl}}/users/{{userId}}
```

Rules for the syntax:

- Names are matched exactly as written, including case. Spaces inside the braces are part of the name, so write `{{baseUrl}}`, not `{{ baseUrl }}`.
- A variable can be used in the URL, query and path-variable rows, header names and values, every body mode, and the fields of [authorization](/guide/authorization).
- A value can contain other variables. They expand recursively to a depth of 10. A name that refers back to itself, directly or through a chain, is left as literal text and is flagged as unresolved.
- A name that no scope defines is left as literal text, for example `{{missing}}` is sent as `{{missing}}`. If the unresolved name is in the URL's host, the send fails with an error instead.
- A variable whose row is disabled, or whose name is empty, does not exist.
- `{{%` starts a [shortcode](#shortcodes), not a variable.

## Precedence

When the same name is defined in several scopes, the highest rank wins.

| Rank | Scope | Where it comes from |
|---|---|---|
| 0 (lowest) | Globals | The workspace-wide `Globals` tab |
| 1 | Collection | The collection's `Variables` tab |
| 2 | Folder | A folder's `Variables` tab. Outer folders first, so the innermost folder wins. |
| 3 | Environment | The active environment |
| 4 | Data | The current row of a runner data file |
| 5 | Runtime | Values set by scripts with `pg.setVar` or `bru.setVar`. They live for the app session and are never written to disk. |
| 6 (highest) | Local | Values set by `pm.variables.set` during one send |

```text
globals      baseUrl = https://api.example.com
environment  baseUrl = http://localhost:8080     <- wins over globals
request URL  {{baseUrl}}/health  ->  http://localhost:8080/health
```

The folders and the collection come from the request's position in the tree, see [Collections](/guide/collections). Scripts can read and write several scopes; see [Scripts and tests](/guide/scripts-and-tests) and the [scripting API](/reference/scripting-api). Folder variables and the data row are read-only to scripts.

## Environments and globals

An **environment** is a named set of variables, for example `Local`, `Staging` or `Production`. Only one environment is active at a time. Choose it from the selector at the right end of the tab strip, or pick `No environment`. The active environment applies to every request in the workspace.

- Create an environment with `+ Create new environment` at the bottom of the selector or from the sidebar. The `...` menu in the editor has `Duplicate`, `Export` and `Delete`. Each environment has a colour dot.
- The editor tab has a table with an enabled checkbox, name, value and an optional description. Search, drag to reorder, and add a row by typing in the empty row at the end. Changes save automatically.
- **Globals** is a single set of variables for the whole workspace. Open it with the `Globals` button in the bottom bar. It has the same editor and the lowest precedence.
- The `Vars` button next to the selector opens a quick look at the active environment, the globals and the current collection's variables. Secret values are masked until you reveal them, and clicking a row copies its value.
- Collections and folders hold their own variables in their detail tabs.

::note
The quick look is read-only: you cannot edit a value or add a variable from it. Setting a variable from selected text in a field, and a pinned environment per collection, are planned and not available.
::

## Chips and autocomplete

Fields that accept variables, such as the URL bar, tint each `{{name}}`:

| Tint | Meaning |
|---|---|
| Accent colour | Resolved from a scope |
| A separate tint | A dynamic variable such as `{{$guid}}` |
| Danger colour | Not defined in any visible scope |

Hover a chip to see its name, scope and value. Secret values stay masked until you hold `Cmd/Ctrl`. Typing `{{` in the URL field opens a list of the variables you can reach, up to eight at a time, filtered as you type.

::note
Dynamic variables are not in the autocomplete list yet, and the hover card cannot edit a value or add the variable to a scope.
::

## Secret variables

Mark a row `Secret` in an environment, the globals, a collection or a folder. A secret variable resolves like any other, with these differences:

- The value is stored in `.postguy/secrets.json` in the [workspace](/guide/workspace), never in the collection or environment file. The file is mode `0600` on Unix.
- The value is masked in the editor. Use `Reveal secrets`, or hold `Cmd/Ctrl`, to see it.
- Wherever Postguy echoes a request, each occurrence of a secret's value is replaced with `•`, one per character and at most 16. This covers the Console, the request saved in History, script failure messages and the recorded URL and headers.
- Environment and globals exports leave secret values out unless they are explicitly included. See [Import and export](/guide/import-export).
- Code snippets keep `{{variables}}` unresolved, so they do not contain the value.

::warning
Secrets are separated from your collections, but they are **not encrypted at rest**. Anyone who can read the workspace folder can read `.postguy/secrets.json`. Keep that file out of version control and backups you share. Masking only hides values in what Postguy displays; a server that echoes a secret back in a response body shows it as received.
::

A secret row whose value is missing from the secrets file resolves to an empty string.

## Dynamic variables

Names that start with `$` are generated when the request is sent. Each occurrence gets a new value.

```text
{
  "id": "{{$guid}}",
  "createdAt": "{{$isoTimestamp}}",
  "email": "{{$randomEmail}}",
  "quantity": {{$randomInt}}
}
```

| Name | Value |
|---|---|
| `$guid`, `$randomUUID` | A random UUID v4 |
| `$timestamp` | The current Unix time in seconds |
| `$isoTimestamp` | The current time as ISO 8601 UTC with milliseconds |
| `$randomInt` | An integer from 0 to 1000 |

Names, people, places, internet values, dates, finance, text and files are also available, and the values come from word lists written for Postguy. An unknown `$name` is left as literal text. The full list is in [Dynamic variables](/reference/dynamic-variables).

## Shortcodes

A shortcode embeds a computed value or the content of a [collection asset](/guide/collections) in a request body. It sits between `{{%` and `%}}`.

```text
{{% base64(file('lib/a.jpg')) %}}
```

| Function | Result |
|---|---|
| `file('path')` | The bytes of the asset at `path`. At the top level the bytes must be UTF-8 text; otherwise wrap them in another function. |
| `text('path')` | The asset as UTF-8 text. An asset that is not UTF-8 is an error. |
| `base64(x)` | Standard Base64 of `x`, with padding |
| `base64url(x)` | URL-safe Base64 of `x`, without padding |
| `hex(x)` | Lowercase hexadecimal of `x` |
| `sha256(x)` | SHA-256 of `x` as lowercase hex |
| `md5(x)` | MD5 of `x` as lowercase hex |

Grammar:

- A call is `name(arg, ...)`. Names are lowercase letters and digits.
- `file` and `text` take exactly one quoted path. The other functions take exactly one argument: a quoted string or another call.
- Strings use `'...'` or `"..."`. Escape a backslash, a single quote or a double quote with a backslash.
- Whitespace is allowed around the call, so `{{%base64(file('a'))%}}` also works.
- `{{variables}}` inside a string argument resolve first, so `{{% text('{{dir}}/note.txt') %}}` reads from the folder that `dir` names.

Limits:

| Limit | Value |
|---|---|
| Call nesting | 8 |
| One shortcode | 4,096 bytes |
| Shortcodes in one text | 1,000 |
| Expanded output | 256 MiB |

### Where shortcodes apply

| Where | Shortcodes |
|---|---|
| Raw body, `x-www-form-urlencoded` values, form-data text values | Yes |
| GraphQL query, variables and operation name | Yes |
| Form-data file rows and the `Binary` body path | Only the exact form `{{% file('name') %}}`, which sends the asset |
| URL, query and path rows, headers, authorization | No |

Shortcodes expand first and the result then goes through normal `{{variable}}` resolution. They need a stored request, because assets belong to a collection. Assets live in `<workspace>/assets/<collection id>/`; manage them in the collection's `Assets` tab. An invalid shortcode, a missing asset or a binary result without `base64(...)` stops the send with an error that names the problem, and the editor marks the shortcode red with the reason. Valid shortcodes are coloured blue.

An asset is capped at 100 MiB, and an import at 2 GiB or 10,000 files.

```text
{
  "name": "avatar",
  "data": "{{% base64(file('images/avatar.png')) %}}",
  "checksum": "{{% sha256(text('images/avatar.txt')) %}}"
}
```

::tip{title="Headless"}
`env_list`, `env_create`, `env_set_active`, `env_get`, `env_set_var` and `env_unset_var` manage environments; `globals_get` and `globals_set_var` manage globals. Both set tools take `secret: true` to keep a value in the secrets file. `variables_resolve` resolves a template and reports each variable's scope, secret flag and unresolved state. `runtime_variables` reads the values scripts set at runtime. `asset_list`, `asset_import`, `asset_rename` and `asset_delete` manage the files shortcodes read. Tools take ids, not names. See [Automation tools](/reference/automation-tools).
::
