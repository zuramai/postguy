---
title: gRPC
description: Call unary and streaming gRPC methods using server reflection, imported .proto files or inline definitions.
---

Postguy calls gRPC methods with a dynamic codec. There is no code generation: you send JSON and get JSON back. Descriptors come from one of three places:

- The server's reflection service.
- `.proto` files in the workspace.
- Inline file lists.

::note
gRPC support is **basic**. The parity file marks most of area D as `partial`, and `d.grpcurl-snippet` and `d.generate-collection` as `planned`. The list under [Not yet](#not-yet) says what is missing. Scripts and the collection runner skip gRPC requests.
::

## Create a gRPC request

1. Select a collection or folder in the sidebar.
2. Open the plus menu and choose `New gRPC request`.

The protocol (HTTP, gRPC or WebSocket) is fixed when a request is created.

Or [import `.proto` files](/guide/import-export#proto-files) to get a collection with one request per method.

## The request tab

| Control | Notes |
|---|---|
| URL field | Placeholder `localhost:50051`. Without a `://` scheme, Postguy adds `http://`, or `https://` when TLS is on. Variables are resolved. |
| `TLS` checkbox | Explicit toggle. Typing a `grpcs://` URL never sets it silently. With TLS off, the connection is plain HTTP/2 (h2c). |
| Method path | Placeholder `package.Service/Method`. `package.Service.Method` is also accepted (the last dot splits the method name). |
| Definition label | Read-only line under the fields: `Server reflection`, ``proto set `<name>` `` or `N inline proto file(s)`. |
| Request message (JSON) | A JSON editor. |
| `Invoke` | Unary call. If the editor holds a JSON array, the first element is sent. |
| `Invoke stream` | Streaming call. A JSON array is sent as the list of messages. Any other JSON value is sent as a single message. |
| `Save` | Appears when the request has unsaved changes. |

`Invoke` and `Invoke stream` do this in order: save the request, resolve variables, call.

The result shows:

- The response JSON.
- The response metadata.
- On failure, one error line: `gRPC status <code>: <message>`, with the numeric status code.

A message that is not valid JSON stops before any call is made.

## Service definitions

| Source | Behaviour |
|---|---|
| Reflection (default) | Tries `grpc.reflection.v1`. Falls back to `v1alpha` if the server answers `UNIMPLEMENTED`. It needs the method path to know which service to resolve. Uses the same TLS settings as the call. |
| Proto set | A named folder `<workspace>/protos/<name>/`. The set is compiled from every `.proto` file in it (up to 256 files, nesting 8). Imports can be relative to the protos root or to the set's own folder. `.proto` import creates this. |
| Inline | A list of files under `<workspace>/protos/` plus extra import folders, also under that root. |

Paths are confined to `<workspace>/protos/`. Absolute paths, `..` and symlinks that leave the root are refused.

The UI shows the definition but does not edit it. To point a request at an inline definition or a different set, edit the request with the `request_update` tool.

## Variables, auth and metadata

- Variables (environment, collection, secrets) are resolved in the URL, method path, message, metadata and definition fields.
- A name that cannot be resolved fails the call instead of being sent literally: `the gRPC request message has unresolved variable(s): …`.
- Inherited auth is applied as metadata.
- API-key-in-query auth is refused for gRPC. Use the header location.
- Metadata keys are lowercased. A key ending in `-bin` is decoded from base64 and sent as binary metadata.
- The editor has no metadata table. Metadata is stored on the request and edited through the tools.

## Calls

- **Unary.** One JSON message in, one out.
- **Server streaming.** One request message (the first array element). Every reply is collected.
- **Client streaming.** The input messages are sent in order. The single reply is returned.
- **Bidirectional.** A finite list of input messages is sent, then all replies are collected.

Limits:

- At most 10,000 input messages are sent. Extras are ignored.
- A reply stream that goes past 10,000 messages ends with `gRPC status 8: response exceeded 10000 messages` (`RESOURCE_EXHAUSTED`).
- Interactive streaming, where you send and end the stream by hand, does not exist yet.

## Example messages

The `grpc_example_message` tool and `.proto` import produce a default JSON object for the method's input type. A cycle guard stops recursive message types.

## TLS and certificates

For gRPC, the TLS toggle is the request's `TLS` checkbox.

Postguy uses the system trust store, the custom CA bundle and the PEM client certificate from [Settings › Certificates](/guide/cookies-proxy-certificates#tls-and-certificates). PEM files are limited to 1 MiB.

There is no insecure (verification off) mode for gRPC.

## Per-request settings

A gRPC request stores `verifySsl`, `serverName`, `includeDefaultFields`, `maxResponseMb` and `deadlineMs`. The engine does not read them, so they have no effect today.

## Not yet

From area D of `parity/postman-features.toml`:

- A grouped method picker. You type the method path by hand; `grpc_describe` lists services and methods.
- A metadata table in the UI.
- Proto-aware completion and saved messages in the editor.
- Interactive Send / End streaming and cancelling a stream.
- Trailers and `grpc-status-details-bin` decoding.
- The server-name (SNI) override.
- A `grpcurl` snippet ([Code snippets](/guide/code-snippets)).
- Script phases (`beforeInvoke`, `onMessage`, `afterResponse` exist in the model but do not run) and runner support.

## Headless

| Tool | Purpose |
|---|---|
| `grpc_describe` | Services, methods, input/output types and streaming flags of a stored request's definition (read-only) |
| `grpc_example_message` | Example input message (read-only) |
| `grpc_invoke` | Unary call; optional `message` overrides the stored one |
| `grpc_stream` | Streaming call with a `messages` array; replies in arrival order |
| `proto_import` | Import `.proto` files into a proto set and collection |

All take the collection and request ids. See [Automation tools](/reference/automation-tools).
